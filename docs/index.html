# FlyRank Research Paper — Webpage Content ## Title **Predicting Search-Performance Decline for Content Prioritization** ### Abstract This study asks whether historical page-level search-performance signals can support the prioritization of pages that may require review. The project constructs a transparent baseline ranking and investigates a Decision Tree classification approach for identifying pages associated with declining performance. The baseline ranks 30,000 anonymized page records using search demand, impressions, CTR opportunity, content age, and average position, while the modeling workflow excludes target-defining fields from the feature set. The available project artifacts establish the baseline queue and leakage controls, but the Decision Tree training and final model-versus-baseline evaluation were not successfully reproduced in the available notebook run, so no unsupported model performance number is reported. The resulting artifact is therefore framed as directional decision support for prioritizing human review rather than as a guaranteed predictor of future search performance. --- ## 1. Introduction / Problem Statement Content teams may have many pages that could potentially benefit from review while available resources for detailed investigation are limited. This project asks whether historical page-level search-performance signals can support a ranked review queue. The goal is not to automatically change content. Instead, the system is intended to help a reviewer decide **which pages deserve attention first**. --- ## 2. Data The analysis uses the anonymized FlyRank ML Internship dataset. **Dataset size:** 30,000 records × 44 columns. The available data contains search-demand, traffic, engagement, content-age, freshness, ranking, and trend-related signals. ### Baseline Features | Signal | Weight | | ------------------ | -----: | | Search volume | 30% | | 90-day impressions | 25% | | CTR opportunity | 20% | | Content age | 15% | | Average position | 10% | The Week-4 baseline ranked all 30,000 records and exported the result to `work/outputs/baseline_action_score.csv`. ### Leakage exclusions The following fields are excluded from predictive features: * `is_declining_label` * `trend_direction` * `trend_pct` The Week-4 audit found **no future-window columns** and **no product-flag columns**. Private client information, private queries, credentials, and other non-public information are excluded from this public artifact. --- ## 3. Methodology ### Baseline The baseline is a transparent weighted ranking based on search opportunity, impressions, CTR opportunity, content age, and average position. ### Machine-learning approach A Decision Tree classifier was selected because the task uses a binary decline label and the model can capture non-linear relationships while remaining relatively interpretable. ### Validation The intended evaluation compares the model with the Week-4 baseline using the same evaluation setup. A grouped/client-level split is also considered as a more conservative validation design because a random row split can allow related records from the same client to appear in both training and evaluation data. ### Leakage control Target-defining fields are excluded from the feature set. The analysis treats leakage control as a requirement rather than an optional optimization. --- ## 4. Results ### Verified baseline result The Week-4 baseline successfully ranked **30,000 records**. The five highest observed baseline scores were: | Rank | Score | | ---: | -------: | | 1 | 0.872991 | | 2 | 0.871854 | | 3 | 0.871525 | | 4 | 0.869534 | | 5 | 0.869047 | ### Model result The available notebook artifacts document the Decision Tree methodology and validation design, but the model training and final comparative evaluation were not successfully reproduced in the captured notebook runs. Therefore, **no unsupported Precision@50 or model-vs-baseline improvement is claimed**. This is an intentional honest-framing choice: results are reported only when supported by an executed evaluation. --- ## 5. Limitations * The final Decision Tree evaluation was not successfully reproduced. * The baseline is a prioritization heuristic, not a causal model. * Historical signals do not establish why a page declines. * Results may not generalize to different datasets, clients, or time periods. * The target definition represents an observable trend rather than complete content quality. * The ranking should be combined with human judgment. The appropriate interpretation is **directional decision support**, not guaranteed future prediction. --- ## 6. Ranked Recommendations ### 1. Prioritize high-scoring pages Use the ranked queue to identify pages that deserve earlier review. ### 2. Investigate the underlying signals Review search demand, impressions, CTR, content age, position, and other available signals. ### 3. Require human confirmation A ranking should guide investigation, not automatically trigger a content change. ### 4. Avoid automated irreversible actions Do not automatically rewrite, delete, publish, or modify content based only on a model score. ### 5. Re-evaluate periodically Monitor evaluation performance and reconsider the model when data distributions or page types change. **Operating principle:** Use the model or ranking to prioritize human attention, not replace human judgment. --- ## 7. Reproducibility Relevant project notebooks: * `w04_baseline_score.ipynb` * `w05_model.ipynb` * `w06_validation_audit.ipynb` * `w07_action_playbook.ipynb` * `capstone.ipynb` The baseline output is: `work/outputs/baseline_action_score.csv` All conclusions should be interpreted together with the assumptions and limitations documented in these notebooks. --- ## 8. Artifacts The research artifact includes: * Baseline scoring methodology * Ranked review queue * Leakage audit * Validation methodology * Action playbook The artifacts are intended to make the analysis inspectable and reproducible rather than presenting the model as a black-box decision maker. --- ## 9.
