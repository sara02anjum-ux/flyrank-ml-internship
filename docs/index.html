Predicting Search-Performance Decline for Content Prioritization

A practical investigation into whether historical page-level search-performance signals can support prioritizing pages for human review.

Abstract

This study asks whether historical page-level search-performance signals can support the prioritization of pages that may require review. The project constructs a transparent baseline ranking and investigates a Decision Tree classification approach for identifying pages associated with declining performance. The baseline ranks 30,000 anonymized page records using search demand, impressions, CTR opportunity, content age, and average position, while the modeling workflow excludes target-defining fields from the feature set. The available project artifacts establish the baseline queue and leakage controls, but the Decision Tree training and final model-versus-baseline evaluation were not successfully reproduced in the available notebook run, so no unsupported model performance number is reported. The resulting artifact is therefore framed as directional decision support for prioritizing human review rather than as a guaranteed predictor of future search performance.

1. Introduction / Problem Statement

Content teams may have many pages that could potentially benefit from review while available resources for detailed investigation are limited.

This project asks whether historical page-level search-performance signals can support a ranked review queue.

The goal is not to automatically change content. Instead, the system is intended to help a reviewer decide which pages deserve attention first.

3. Methodology

Baseline

The baseline is a transparent weighted ranking based on search opportunity, impressions, CTR opportunity, content age, and average position.

Machine-Learning Approach

A Decision Tree classifier was selected because the task uses a binary decline label and the model can capture non-linear relationships while remaining relatively interpretable.

Validation

The intended evaluation compares the model with the Week-4 baseline using the same evaluation setup. A grouped/client-level split is also considered as a more conservative validation design because a random row split can allow related records from the same client to appear in both training and evaluation data.

Leakage Control

Target-defining fields are excluded from the feature set. Leakage control is treated as a core requirement of the modeling workflow.

5. Limitations & Honest Framing

  • The final Decision Tree evaluation was not successfully reproduced.
  • The baseline is a prioritization heuristic, not a causal model.
  • Historical signals do not establish why a page declines.
  • Results may not generalize to different datasets, clients, or time periods.
  • The target definition represents an observable trend rather than complete content quality.
  • The ranking should be combined with human judgment.

The appropriate interpretation is directional decision support, not guaranteed future prediction.

6. Ranked Recommendations

1. Prioritize high-scoring pages

Use the ranked queue to identify pages that deserve earlier review.

2. Investigate the underlying signals

Review search demand, impressions, CTR, content age, position, and other available signals.

3. Require human confirmation

A ranking should guide investigation, not automatically trigger a content change.

4. Avoid automated irreversible actions

Do not automatically rewrite, delete, publish, or modify content based only on a model score.

5. Re-evaluate periodically

Monitor evaluation performance and reconsider the model when data distributions or page types change.

Use the model or ranking to prioritize human attention, not replace human judgment.
